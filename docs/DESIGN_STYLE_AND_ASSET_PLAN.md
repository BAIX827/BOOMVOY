# BOOMVOY 设计风格与插画素材实施计划

更新日期：2026-10-15
用途：记录本次讨论中的选择、视觉参考、素材需求和实施顺序，供以后分批修改页面、生成素材时接着使用。

## 1. 当前决定与进度

### 已确认的方向

- 用户偏好 C「旅行手账」示意图中的插画、路线、纸张、票根和 Boomi 所形成的整体感觉。
- 原图右侧旅行本需要重做，重点改善厚紫色边框、金属线圈和笨重的纸面装饰。
- 插画采用预先制作、保存、反复使用的方式；页面通过素材组合和代码绘制呈现不同旅行。
- 用户会以后逐步修改和生成素材，本次先完成记录。
- 长期目标是形成用户自己的跨产品设计语言，让旅行、听课和 Pet 产品拥有共同的作者气质。!Boring 用于研究设计方法，具体形象、材质和交互需要发展出自己的表达。

### 已提出、待实际原型确认的方案

- 新版旅行本：细鼠尾草绿布面书脊、自然白纸面、轻薄页边、小页签和书签。
- 手机总览采用单栏，旅行本单独成页；底部使用「总览／行程／旅行本／更多」。
- 旅行本以「清单／票夹／随记」组织内容。
- 动效体现轻微重量、连续反馈和稳定落位，先做少量交互实验再确定参数。

这些方案目前保存在概念图中，页面结构、导航映射和动效需要在实现阶段核对。正式业务页面与独立插画素材尚未按此方案制作。

## 3. 希望形成的样子

### 页面和材质

- 自然纸色作为底面，深墨蓝承担主要文字，暖黄色强调日期或当前待办，绿色用于主要操作。
- 插画采用细墨线与轻水彩的组合，保留笔触和地方特征，控制密度。
- 本子、票根、照片和路线承担具体内容，每种形式对应可用的信息或操作。
- 本子外观通过细书脊、少量纸页边缘和页签表达，控件与正文保持清晰。
- 页面留白围绕阅读和操作安排，当前旅行、待完成事项和当天行程拥有明确主次。

### 字体与文案

- 功能正文、按钮、日期与金额使用易读的中英文字体。
- 标题可以有适量书籍感；手写字用于用户自己的随记或少量有意义的标注。
- UI 通过标题、按钮、标签、用户内容、数据和状态表达用途。
- 通用功能介绍、重复小字和装饰口号在落地时删去。填写规则、权限、错误和操作后果保留必要提示。
- 中英文界面分别检查长度，城市名与日期由本地化代码输出。

### 跨产品的共同气质

可以逐步建立统一的形状、边缘、运动节奏、声音风格和角色回应。具体对象随用途变化：

- 旅行：地点加入路线，照片记录到访，票据归入票夹。
- 听课：书签落在录音时间点，展开后连接笔记与原音频。
- Pet：物品有位置，宠物对物品和用户动作作出回应。

上述听课与 Pet 内容属于长期探索，待对应项目确认需求后再实施。BOOMVOY 的城市插画和 Boomi 保持自身的产品身份。

## 4. 桌面与手机怎么排

### 桌面总览

- 顶部：旅行名称、日期、人数及必要操作。
- 主栏：城市插画路线、当前待办和当天时间线。
- 辅栏：新版旅行本，提供清单、票夹和随记入口。
- 插画路线支持进入对应城市或日期；「查看路线」进入现有地图功能。
- Boomi 提供稳定入口，避免遮住时间线、票据或按钮。

### 手机总览

按下列阅读顺序组织单栏内容：

1. 返回入口、品牌和 Boomi 入口。
2. 旅行名称、日期、天数和人数。
3. 适合窄屏的紧凑插画路线，以及「查看路线」。
4. 当前最需要处理的一条待办。
5. 当天日期、天气和行程时间线。
6. 添加地点等当前页面操作。
7. 固定底部导航与手机安全区。

城市插画在手机上重新安排位置和数量。城市较多时采用可滚动城市序列或当前城市摘要；具体方式通过实际长行程原型选择。文字保持正常字号，插画区域避免挤掉当天行程。

### 手机旅行本

- 单独成页，顶部保留「清单／票夹／随记」切换。
- 清单展示准备事项，完成状态来自真实数据。
- 票夹展示机票、住宿、门票等已登记记录，点击查看详情。
- 随记展示用户自己的内容，可逐步加入照片。
- 长内容采用页面滚动，底部导航持续可用。

### 导航与现有数据的衔接

当前项目已有预订、行李、笔记、打卡手账等页面。新增「旅行本」时先确定它如何聚合这些入口与记录，保持单一数据来源。

- 「票夹」优先复用现有预订登记数据。
- 「清单」需要区分准备待办与已有行李清单。
- 「随记」需要明确与旅行设置笔记、打卡手账的关系。
- 手机「更多」保留预算、AA、天气、同伴、设置等功能入口。
- 四项底部导航与现有五组导航的映射，在实现前列出并检查所有旧入口。

## 5. 插画如何复用与控制费用

工作方式：制作素材 → 保存文件 → 建立城市与素材对应关系 → 页面加载 → 按旅行数据排版。

- 打开页面、切换城市、调整日期、拖动行程及切换手机布局均使用已有素材和前端代码。
- 新增城市时先匹配已有城市素材，再选择适合的城市、山海、乡村等通用插画。
- 需要专属地标时，单独补充该城市素材。
- 生成图片属于制作阶段的费用，计费随所用服务和模型规则而变化；文本提示与图像处理可能分别计入用量。
- 图片加载涉及文件大小、存储和流量；行程推荐、聊天、地图和天气服务的用量分别计算。
- 此方案中的插画展示流程通过静态图片完成，日常使用无需为插画发起模型请求。

## 6. 素材清单

按下面顺序分批制作，先用日本示例旅行跑通一套完整页面。

### 第一批：最小可用素材

- [ ] 东京：一张可独立摆放的城市地标组合。
- [ ] 富士：一张以富士山及湖岸为主的组合。
- [ ] 京都：一张寺庙、街巷或塔楼组合。
- [ ] 大阪：一张具有当地辨识度的城市组合。
- [ ] 通用城市、山地、海岸、乡村各一张，用作缺少专属素材时的封面。
- [ ] 从现有 Boomi 原稿确认角色比例、服装、主色和线条，建立固定参考。

城市素材承担场景插画；城市名称、日期、天数、路线点和连线由代码输出。

### 第二批：可共享的小素材

- [ ] 云、树、山、海岸、水面、灌木等少量自然元素。
- [ ] 供插画拼接使用的火车、飞机、相机和行李元素。
- [ ] 必要时制作轻纸纹和布面书脊纹理。
- [ ] 按实际旅行需求增加其他城市，优先补用户常用目的地。

功能图标继续使用统一的现有图标系统；简单路线、虚线、票根切口和书页边缘由代码绘制。

### 第三批：Boomi 状态

- [ ] 默认待机。
- [ ] 指向当前操作。
- [ ] 拿地图或查看路线。
- [ ] 完成记录后的简短回应。

先确认固定形象，再按需求补姿势。现有角色文件见 [boomi.png](../src/assets/boomi.png) 与 [boomi_icon.png](../src/assets/boomi_icon.png)。

## 7. 素材制作规范

### 风格与构图

- 将选定 C 图作为画风参考，Boomi 使用现有角色原图作为身份参考。
- 城市素材统一线条深浅、水彩饱和度、视角、地面位置和留白比例。
- 每张城市组合独立构图，边缘适合与纸面衔接。
- 用少量地标建立辨识度，组合完整度通过实际桌面及手机页面检查。
- 季节素材按需要补充；普通版本优先选择适合全年使用的地标与植被。
- 地理定位、地图路线和交通数据由现有地图与行程逻辑处理。

### 文件与版本

- 透明插画保留透明通道；母版优先保留原始高分辨率 PNG。
- 页面使用经过检查的 WebP 或 PNG，结合真实显示尺寸决定导出大小。
- 母版按实际显示尺寸的约两倍准备，避免持续加载超过需要的大图。
- 正式图片使用稳定英文文件名，例如 `tokyo-v1.png`、`fuji-v1.png`。
- 修改稿另存版本，确认后再更新页面引用。
- 每批记录提示词、参考图、生成工具、版本和已知问题。
- 城市名、日期、价格、预订状态和可操作按钮作为真实页面元素单独渲染，保证可编辑、本地化与可访问性。

## 8. 可复用生成提示词

下面是以后补城市素材时的起点，每次替换方括号内容，并附上确认后的参考图。

```text
为 BOOMVOY 旅行手账制作一张独立的城市插画素材。
城市：[城市名称]。
地标：[选定的 1–3 个地标]。
参考图角色：选定的 C 图用于画风；已确认城市素材用于视角、线条和配色一致性。
画法：细墨蓝线稿、轻水彩上色，暖黄色与柔和绿色点缀，自然纸面上清晰可读。
构图：横向、独立成组、底部基线稳定、四周留出组合空间，适合桌面和手机重新排版。
输出：透明背景，高分辨率 PNG，主体边缘干净，保留水彩细节。
画面只包含指定的城市与景物；城市文字、日期、路线、按钮由页面代码另外呈现。
```

生成后先查看透明边缘、地标辨识度、缩小后的清晰度和与上一批素材的风格差异，再决定采用或单独修订。

## 9. 页面代码承担的内容

- 旅行名称、日期、人数、城市标签和时间线。
- 城市序列对应的路线点、连线、选中和完成状态。
- 票根、书脊、页签、纸页边缘及大部分简单装饰。
- 桌面双栏、手机单栏与安全区布局。
- 城市与插画文件的小型映射表，以及缺失素材的通用回退。
- 点击、拖动、切换与完成记录的反馈。

页面复杂度增加时再拆分组件。可以先规划城市插画路线、旅行本、票据卡和当天时间线四类组件，复用项目现有数据和操作。

## 10. 以后按什么顺序做

### 阶段一：确认新版旅行本与手机内容顺序

- [ ] 核对参考图，确定纸色、书脊、页签及标题比例。
- [ ] 删除示意图中的装饰口号与重复功能介绍。
- [ ] 明确旅行本三个分类与现有数据、页面的映射。
- [ ] 用长城市名、多城市、空旅行和长票据内容检查布局。
- [ ] 决定现有 cream／ocean／forest 三套主题如何共享这套视觉；先记录方案再调整主题配置。

完成结果：一套清楚的桌面与手机结构，以及首批素材制作规格。

### 阶段二：先验证一张城市素材

- [ ] 生成或修订一张独立城市插画，推荐先用东京。
- [ ] 放进实际桌面与手机原型检查缩放、透明边缘和文字位置。
- [ ] 确认后以它作为后续城市的风格参考。
- [ ] 补齐富士、京都、大阪与通用回退素材。

完成结果：首批可供代码调用的素材文件与对应提示词。

### 阶段三：实现总览与旅行本

- [ ] 建立城市素材映射与通用回退。
- [ ] 实现插画路线，按旅行数据生成标签与连线。
- [ ] 修改旅行总览及新版旅行本。
- [ ] 完成手机导航与旧功能入口衔接。
- [ ] 接入真实待办、票据和笔记，保留已有编辑与登记行为。
- [ ] 检查原有主题、本地化、持久化和分享入口。

完成结果：真实数据驱动的桌面与手机页面。

### 阶段四：打磨个人交互风格

- [ ] 选择添加地点、完成待办、打开票夹中的一个先做交互原型。
- [ ] 确认按压、拖动和落位的反馈，再复用到其他操作。
- [ ] 大部分操作快速完成；连续使用时检查节奏和干扰。
- [ ] 支持键盘、触屏与减少动态效果的系统偏好。
- [ ] 若以后增加音效，提供开关并验证静音使用；Web 端根据浏览器能力选择反馈方式。

完成结果：可复用的组件与交互规则，作为以后听课和 Pet 项目的参考。

### 阶段五：按需要扩充

- [ ] 增加新城市插画与少量 Boomi 姿势。
- [ ] 将风格扩展到发现、打卡手账和分享页面。
- [ ] 根据真实需求制作季节变体或个性化封面。

## 11. 每阶段怎么检查

- 在约 360、390、768、1024、1440px 宽度检查内容重排，具体断点随内容确定。
- 手机常用正文以 16px 为起点，主要点击区域至少 44×44 CSS px。
- 检查底部导航、安全区、软键盘以及 Boomi 入口的遮挡情况。
- 检查中英文、长城市名、无图片、无票据和多城市旅行。
- 文字与按钮是真实 UI 元素；有意义的图片提供适当文本，纯装饰图片采用装饰标记。
- 检查素材加载体积、失败回退、透明边缘和部署路径。
- 确认打开页面、切换行程和调整顺序只加载已有素材、运行页面代码。
- 代码修改后运行项目适用的检查，重点验证导航与现有旅行功能。
